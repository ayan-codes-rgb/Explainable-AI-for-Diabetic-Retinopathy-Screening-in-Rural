Your current folder isn't the repo. genpath('common') returns an empty string and addpath silently does nothing. Run pwd, then cd to the repo root first. This has already cost us an hour once.

§2The contract — four rules, none optional

Rule 1 · Never call imread()

Every image enters the pipeline through loadFundus() in common/. Not negotiable, and here's why it matters concretely.

A colour image is three stacked grids — red, green, blue. In fundus imaging the green channel carries almost all the signal: vessels and lesions have their strongest contrast there, red is saturated, blue is noise. So nearly every module has a line like img(:,:,2). If two of us load images with different channel ordering, one person's "green channel" is silently someone else's blue, their module produces garbage, and nothing throws an error. You find out on integration day.

Same story for bit depth (IDRiD grading images are 8-bit JPEG, DRIVE ships 16-bit TIFF — a threshold of 0.06 means "6% brightness" on one and "keep everything" on the other) and for resolution.

What loadFundus guarantees

OutputTypeGuarantee
imguint8 H×W×3RGB order, 0–255, retina centred and square, pixels outside the retina forced to 0
fovMasklogical H×Wtrue inside the retina, same size as img
geomstructrecord of every geometric operation applied — needed to realign ground truth

Internally it forces 3-channel RGB uint8, finds the retina, crops the black border away, pads the crop to a square before resizing (resizing a 4:3 fundus straight to 512×512 turns the retina into an ellipse and corrupts vessel geometry, lesion shape and optic-disc circularity all at once), then resizes.

Rule 2 · Realign your ground truth, always

The loader crops and resizes. Ground truth that doesn't go through the identical transform is misaligned by tens of pixels. It will not error. It will just make every metric you compute wrong, quietly.

[img, fov, geom] = loadFundus('…/IDRiD_01.jpg');

% pixel masks — IDRiD lesions, DRIVE vessels, optic disc
maMask = applyFundusGeom(imread('IDRiD_01_MA.tif') > 0, geom);

% coordinates — optic disc centre, fovea centre, MA locations
odXY   = mapFundusPoints([odX odY], geom);

Both functions take the annotation at its original resolution and error if you pass a pre-resized one. Masks resize with nearest-neighbour — bilinear would average a 0 next to a 1 into 0.5, a label value that doesn't exist.

Rule 3 · Only M1 edits common/

Need a change in the loader? Ask. Don't patch it on your branch — you'll be running different preprocessing from everyone else and you won't know it. If you need extra preprocessing for your own module, wrap the loader rather than modifying it; grading/makeGradingReadFcn.m is a worked example of doing exactly that.

Rule 4 · Don't commit to main

Work on your branch, open a Pull Request when your piece runs. Broken main blocks six people. And never commit anything under data/ — .gitignore handles it, but run git status before you commit and look.

§3The data — what you actually have

Two datasets, both pre-labelled by clinicians years ago. Nobody on this team labels anything. Grading a fundus image needs medical training; that work is already done and it's why we use public datasets.

DatasetImagesSourceGround truth
IDRiD516one eye clinic, Nanded, Maharashtra — one camera, uniform 4288×2848DR grade 0–4, macular oedema risk, pixel lesion masks, disc/fovea coordinates
APTOS 20193,662Aravind Eye Hospital — technicians travelling to villages, many cameras, wildly variable qualityDR grade 0–4 only

APTOS is the training volume. IDRiD is the ground truth. APTOS's messiness is not a defect — it is the deployment condition the problem statement describes, and it's what makes M1's quality module demonstrably useful. IDRiD is the only source of pixel-level lesion annotation in the entire project, and it's what lets us claim validation on Indian fundus cameras.

Three traps in this folder

Missing soft-exudate files mean "none present", not "unlabelled". Only 26 of 54 training images have one. Skip those images and you throw away every negative example.

A. Segmentation uses different filenames. Its images are IDRiD_01.jpg (two digits); B and C use IDRiD_001.jpg (three). Zero overlap — verified. You cannot join A's masks to B's grades by filename.

The optic disc mask exists to be subtracted. The disc is bright and yellow-white; so are hard exudates. Any brightness-based exudate detector will flag the optic disc on every single image with high confidence. Standard move: find bright regions → delete anything inside the disc → what remains is exudate. This is why M2's disc work blocks M3's exudate work.

Referable DR (grade ≥ 2) is 62.6% of IDRiD but only 40.6% of APTOS — IDRiD is clinic-collected, APTOS is a screening population. Grade 3 is the scarcest class and it sits on the referable side, so errors there cost sensitivity, which carries the tighter >90% target.

The 0–4 scale, decoded

NPDR = non-proliferative (damage, no new vessels). PDR = proliferative (the eye has started growing fragile new vessels, which bleed and can detach the retina — this is what actually causes sudden blindness).

  • 0 nothing · 1 microaneurysms only · 2 + haemorrhages or exudates · 3 lots of the above, widespread · 4 new vessels growing
  • Referable = grade ≥ 2. That single binary call is the entire clinical decision the system exists to make.
  • Sensitivity = of people who really need referral, what fraction did we catch. Missing one means someone loses their sight — hence >90%.
  • Specificity = of healthy people, what fraction we correctly left alone. A false alarm costs one wasted appointment — hence the looser >85%.

§5Findings the whole team should know

Your test set has to be big enough to measure with

Six different model configurations were tried. Here is every IDRiD test AUC they produced, with the measurement error on each:

The spread across all six is 0.042. The measurement error on each single one is ±0.036. They are the same number. Days were spent reacting to differences that were pure noise — treating a "drop" as a regression and a "rise" as progress.

This applies directly to M2 and M3, who will validate on 81 images. That is an even smaller sample. Before you conclude that version B of your detector beats version A, work out whether your test set can actually tell them apart. Report confidence intervals, not bare percentages.

Models don't transfer between populations

The grading model scores AUC 0.973 on APTOS-like images and 0.867 on IDRiD. Same model, same day. APTOS is a screening population — half of it obviously normal, easy to separate. IDRiD is clinic-collected, 62% referable, dense with borderline grade-1-vs-2 cases where the whole question is whether small red dots are microaneurysms alone or accompanied by a haemorrhage.

This is a real, quantified finding about deployment, and it belongs in the final report and the pitch. It is exactly the failure mode the problem statement warns about with existing AI solutions.

Things that made no difference

Worth knowing so nobody repeats them: 10× more training data, 4× resolution, Ben Graham preprocessing, domain weighting, and recalibration all left IDRiD test performance flat. The reason is that the feature extractor was frozen — a network trained on cats and furniture, with no mechanism to learn to look harder at microaneurysms. Sharper inputs don't help a fixed function. Fine-tuning is what unlocks them.

§6Your module

Read your own block completely. Each lists what you own, what data you have, what to build first, what to measure, and the specific things that will waste your time if nobody warns you.

M1 Image quality assessment & enhancement Start now
Owns
quality/ and common/ (you are the only person who edits the loader)
Fills
result.quality, result.enhancedImage
Data
All of APTOS — it's full of genuinely bad images, which is what makes this module demonstrable
Blocks
Nobody, but everyone depends on your loader staying stable

Build first

  1. Focus check — variance of the Laplacian. A blurred image has little high-frequency energy. Compute it on the green channel.
  2. Illumination check — mean and standard deviation of the green channel. Too dark, too bright, or too uneven all fail.
  3. Field-of-view check — is enough retina actually in frame? fundusFOVMask already gives you the retina; check its area and whether it's clipped at the edges.
  4. Enhancement — adapthisteq for CLAHE, imbilatfilt or wiener2 for denoising. Apply to borderline images only; over-processing a good image makes it worse.
Compute every statistic inside the mask

loadFundus returns fovMask. Roughly 25–30% of a processed frame is black border. Include it and your illumination mean is dominated by pixels carrying no information, and your focus variance is diluted by a perfectly flat region. Use img(fovMask), not img(:).

Measure

You have no labelled quality ground truth, so build your own: pick ~50 APTOS images, sort them by eye into gradable / borderline / ungradable, and report agreement between your classifier and that. Say plainly in the report that the reference is your own labelling, not a clinician's.

The clinically important part

An ungradable image must be flagged for recapture, never silently guessed at. Guessing on an unreadable image is precisely how a screening programme misses someone. Your reject path needs a human-readable reason ("too dark", "out of focus", "retina partially out of frame") because in the field a technician has to act on it.

M2 Optic disc, fovea, vessels Start now
Owns
segmentation/
Fills
result.opticDisc, result.fovea, result.vesselMask
Data
C. Localization — disc and fovea centre coordinates for all 516 images. A. Segmentation folder 5 — 81 optic-disc pixel masks.
Blocks
M3. They cannot reliably detect exudates until you can locate the disc.

Build first

  1. Optic disc — the brightest large blob. Try imfindcircles (Hough) on the green channel, or threshold the brightest percentile and take the largest connected component.
  2. Fovea — the darkest region roughly 2–2.5 disc-diameters from the disc, along the vascular arcade. Start with a fixed-distance search and refine.
  3. Vessels — matched filtering with Gaussian-derivative kernels, or top-hat with a disk strel.

Measure — you have real ground truth, use it from day one

Don't eyeball your output. C. Localization gives you the true centres, so you can report mean Euclidean error in pixels immediately, plus the fraction of images where you land within one disc radius. That's a real number for the report from your first working version.

[img, fov, geom] = loadFundus(imgPath);
trueXY = mapFundusPoints([odX odY], geom);   % from the CSV
err    = hypot(predXY(1)-trueXY(1), predXY(2)-trueXY(2));

Use mapFundusPoints or your coordinates will be in the original 4288×2848 frame while your prediction is in the 512×512 one, and every error you compute will be nonsense.

Why the fovea matters clinically

A lesion near the fovea threatens vision far more than the same lesion at the periphery — the fovea is where your reading vision lives. Locating it isn't bookkeeping; it's what lets M5 say "this lesion is sight-threatening" rather than just "a lesion exists".

M3 Lesion detection Start now
Owns
lesions/
Fills
result.maList, result.exudateMask, result.haemorrhageMask, result.neoFlag
Data
A. Segmentation — 81 images, 363 hand-traced masks. This is the only pixel-level ground truth in the whole project.
Depends on
M2's optic disc for exudate detection

Build first

  1. Candidate generation — top-hat morphological filtering (imtophat / imbothat) on the green channel. This finds small bright or dark structures against the background. Candidates only today; classification comes after.
  2. Microaneurysm vs noise — shape, size and contrast features into a simple classifier (fitcsvm). MAs are small, round, dark red.
  3. Haemorrhages — same colour family as MAs, separated by size and shape irregularity. That distinction is literally the grade-1 / grade-2 boundary, which is the referral line.
  4. Exudates — colour thresholding in Lab space, then subtract the optic disc.
  5. Neovascularisation — abnormal vessel density and tortuosity near the disc or periphery. Genuinely hard even in published work. Do not over-engineer this; a heuristic with an honest caveat is the right answer on this timeline.

Measure

Per-image sensitivity and false positives per image, against the masks. An FROC-style curve if you have time. Report the sample size loudly — 81 images, 54 of them training.

The three things that will cost you a day

Run every mask through applyFundusGeom with the geom from that image's own loadFundus call. Misalignment doesn't error; it just makes your scores meaningless.

Missing soft-exudate mask = no soft exudates. Not "unlabelled". Treat those 28 images as negatives.

A. Segmentation filenames differ from B and C. IDRiD_01 here, IDRiD_001 there, no overlap. Never join them by name.

Today, while you're blocked

Read MATLAB's built-in gradCAM (Deep Learning Toolbox) and sketch the report layout on paper. You can run gradCAM against the existing baseline model as soon as M4 hands it over.

The claim you have to support

The problem statement asks for "lesion-level evidence correlated with clinical criteria". That is a specific, checkable claim and it needs two things combined:

  • Grad-CAM shows where the model looked. On its own that's a pretty heatmap and nothing more.
  • M3's masks show where disease actually is.

The overlap between the two is the entire explainability argument: "the model's attention concentrated on this region, and that region contains 3 confirmed microaneurysms." It can only be verified on A. Segmentation's 81 images, so build around that constraint from the start.

Also yours

  • Confidence calibration — temperature or Platt scaling against a validation set, checked with a reliability diagram. A model saying "0.9" should be right about 90% of the time.
  • Automated annotated report — image, overlays, grade, confidence, exported as PDF or figure.
  • Review screen in App Designer, and actually time two teammates doing a mock ophthalmologist review. The <30 s claim in the problem statement needs a measurement behind it, not an assertion.

Simulink — build first

A block diagram skeleton with placeholder rates: source → enhancement → segmentation → grading → review, as subsystems. Then fill the placeholders with real estimates — patients per day, image size 5–10 MB, rural bandwidth — so it produces a first throughput number.

The full version models this as a queueing problem: arrival rate against service rate, with a review-time distribution. That's where "optimising resource allocation for 100,000+ patients annually" gets an actual number attached to it.

Check for SimEvents

Plain Simulink is clumsy at queueing; SimEvents is built for exactly it. It was not in the toolbox list on the machine we checked. Put it in the same licence request as anything else missing, today — and don't block on it, plain Simulink can approximate for the POC.

One number from M4 worth modelling: at the current operating point the system refers roughly 28% of healthy people unnecessarily. Across 100,000 screenings that's tens of thousands of extra appointments against about one ophthalmologist per 100,000 rural population. That trade-off is your model's insight.

Integration — Day 4, and budget the whole day

Wire every module into one analyzeImage() per the shared struct, then run the full pipeline on 30–50 sample images end to end. This is the highest-risk day in the schedule. No new features that day — only plumbing. The struct contract exists precisely so this is boring.
